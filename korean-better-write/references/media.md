# 매체별 편집

해당 매체의 부분만 적용한다. 독자나 사용 상황이 다르면 이 기본값보다 실제 요청을 따른다.

## PPT와 발표 대본

화면을 보며 대본을 듣는 발표인지, 슬라이드만 배포하는 자료인지 먼저 구분한다.

- 함께 보는 발표에서는 화면과 말을 한 묶음으로 판단한다. 모든 사실을 양쪽에 복제하지 않는다. 화면에 있다는 이유로 중요한 설명이나 강조를 모두 말에서 빼지도 않는다.
- 화면에는 한눈에 찾아야 할 구조, 수치, 절차, 예시를 둔다. 대본은 청중이 화면에서 무엇을 봐야 하는지 짚거나 관계·이유를 설명한다. 화면을 그대로 낭독하는 길이가 길어지면 줄인다.
- 앞 장에서 예고하고 해당 장에서 설명하고 다음 장에서 다시 정리하는 반복이 필요한지 전체 흐름으로 확인한다. 짧은 발표에 자동으로 도입·요약·맺음말을 추가하지 않는다.
- 작성자의 해설, 검수 과정, 실제 업무와 관계없는 면책 문구를 대본에 넣지 않는다. 예시 표시나 출처가 필요한 곳에는 남긴다.
- 무대 전환이나 시연 조작은 발표자 메모로 구분한다. 말로 읽을 대본에 편집 지시를 섞지 않는다.
- 슬라이드만 배포한다면 이해에 필수적인 설명을 대본에만 숨겨 두지 않는다.

## 매뉴얼과 도움말

- 독자가 하려는 일을 기준으로 시작 위치, 조작, 결과를 연결한다. 실제 화면 라벨과 검증된 동작을 쓴다.
- 작업을 바꾸는 입력 조건·권한·저장 여부·예외는 보존한다. 모든 절에 동일한 일반 주의사항을 붙이지 않는다.
- 스크린샷은 위치와 상태를 보여 주고, 본문은 무엇을 왜 해야 하는지 설명한다. 이미지 속 문구를 장황하게 다시 적지 않는다. 검색과 접근성에 필요한 텍스트는 남긴다.
- 독자가 검색으로 개별 절에 들어오면 그 절에서 필요한 최소 맥락을 제공한다. 앞 절에 있다는 이유만으로 안내를 빼지 않는다.

## 책·긴 글·에세이

- 독자가 이해하고 생각하거나 느끼는 경험도 내용의 역할이다. 즉시 행동을 바꾸지 않는다는 이유로 삭제하지 않는다.
- 사례, 비유, 장면, 여백이 설명·정서·리듬에 기여하는지 본다. 글쓴이의 개성과 의도적인 반복을 일괄 제거하지 않는다.
- 장 사이의 반복이 독자의 기억을 돕는지, 같은 주장을 늘리는지 구분한다. 짧은 UI 문구처럼 모든 문단을 압축하지 않는다.
- 근거 없는 일화나 수치를 자연스러움을 위해 보태지 않는다. 핵심 주장과 반론의 조건을 유지한다.

## 보고서·제안서·업무 메일

읽는 사람이 판단할 내용과 그 근거를 쉽게 찾게 한다. 이미 아는 배경을 줄이되 의사결정에 영향을 주는 조건과 불확실성은 남긴다. 인사와 관계를 고려한 표현은 실제 관계에 맞게 유지한다.
