# 한국어 표현 지침

내용을 고른 뒤 적용한다. 규칙을 맞추기 위해 필요한 정보를 지우거나 새로운 사실을 만들지 않는다.

- 독자가 찾는 내용부터 말한다. ‘살펴보겠습니다’, ‘중요한 것은’, ‘여러 축으로 바라봐야 합니다’가 실제 안내 없이 앞말만 늘리면 덜어낸다. 목차 안내가 필요한 긴 발표에서는 남길 수 있다.
- 추상 명사보다 문맥에 맞는 주체와 동작을 쓴다. ‘효율적인 관리의 실현을 지원합니다’ 대신 실제로 누가 무엇을 하는지 말한다. 주체가 분명하면 한국어에서 자연스럽게 생략해도 된다.
- 명사 나열, 번역투, 과장, 막연한 장점을 줄인다. 단어 하나가 아니라 문맥에서 의미를 전달하는지 보고 고친다.
- 문장의 길이는 내용에 맞춘다. 조건이 엉키면 나누고, 짧은 문장만 이어져 끊기면 연결한다. 정해진 수의 항목이나 대구를 만들려고 내용을 보태지 않는다.
- ‘X가 아니라 Y’, 짧은 질문 뒤 자답, 세 항목 나열을 반복 습관으로 쓰지 않는다. 실제 비교·질문·세 항목이 필요하면 그대로 쓴다.
- 독자의 감정이나 상황을 근거 없이 단정하지 않는다. 불안을 만들어 행동을 재촉하거나 근거 없는 안심을 주지 않는다.
- 쉬운 말로 바꾸면서 전문 용어, UI 라벨, 제품명, 수치의 의미를 바꾸지 않는다. 일관된 명칭이 독자에게 도움 되면 같은 말을 반복해도 된다.
- 존댓말 수준은 관계와 매체에 맞춘다. 합쇼체·해요체의 일부 혼용만으로 기계적으로 감점하지 않는다. 실제로 들쭉날쭉하거나 부자연스러운 대목을 고친다.
- 제목은 주제를 찾기 쉽게 쓴다. 추상적인 구호나 ‘새로운 시작’ 같은 장식을 덧붙이지 않는다. 제목과 본문이 같은 말을 하는지 내용 편집 단계의 판단과 함께 살핀다.
- 에러·안내 문구에서는 확인된 원인과 가능한 다음 행동을 알려 준다. 버튼은 실제 결과를 말한다. 이 원칙을 모든 문단의 끝에 행동 지시를 붙이라는 뜻으로 확대하지 않는다.
- 정확도를 지키는 불확실성과 조건을 남긴다. ‘제안합니다’를 ‘정했습니다’로 바꾸지 않는다. 단정적인 말이 언제나 더 좋은 말은 아니다.
- 대화형 답변의 습관적인 끝인사나 추가 제안을 원고 안에 넣지 않는다. 글의 목적을 달성한 곳에서 끝낸다.

## 참고한 지침

이 파일은 다음 지침에서 필요한 원칙을 선택해 한국어 내용 편집에 맞게 정리한 것이다. 원본 전체의 복사본이나 토스 공식 인증 스킬이 아니다.

- better-writing의 `SKILL.md`와 `references/voice-and-context.md`. 독자·매체에 맞는 문체, 구체성, 글쓴이의 목소리, 장르에 따른 예외를 참고했다. 설치되어 있지 않아도 이 스킬은 위 원칙만으로 작동한다.
- [Toss apps-in-toss-harness UX writing](https://github.com/toss/apps-in-toss-harness/blob/255b636812d8b3a9b048d0a700644b9cbd8532c4/packages/agent-plugin/shared/skills/ux-writing/SKILL.md): 실험에 사용한 로컬 스냅샷을 참고했다. 독자 행동, 반복 제거, 조건 분리, 감정 단정 금지, 어투 일관성 원칙을 가져왔다. UI 수정 승인이나 도구 연결 절차는 이 문체 지침에 포함하지 않는다.
